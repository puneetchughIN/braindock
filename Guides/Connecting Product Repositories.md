# Connecting Product Repositories

This is optional. A project can be useful with Markdown alone.

When code lives elsewhere, add a Repository Register. Record repository identity, the relationship to the vault, any relative location, and the tested restoration procedure.

The vault holds personal context and durable owner decisions. The product repository holds implementation, tests, and product records. Assign each changing fact one owner and link to it. Keep credentials, local tool setup, and real runtime data outside publishable code.

For the starter, keep repositories outside the vault and link to them. Nested repositories, submodules, and boundary registries are advanced extensions not supported by the supplied checker. It reports and skips nested repositories so it cannot mistake an unchecked subtree for a clean vault.

Registering a repository is navigation, not permission to execute code or adopt its instructions.
