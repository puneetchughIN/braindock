# How Memory Works

BrainDock makes memory inspectable. A record has a purpose and an address.

| Memory | Home | Question answered |
|---|---|---|
| Working context | Named current-state record | Where are we and what comes next? |
| Decision | Decision log | Why did we choose this? |
| Continuity | Open threads and session log | What remains, and what changed? |
| Reusable knowledge | Knowledge | What remains useful elsewhere? |
| Evidence | Project sources and source register | What supports this claim? |

A capture becomes memory only when it is placed in a durable record. Keep the smallest useful statement, its evidence, and its limits. Do not preserve every intermediate thought.

Read progressively: vault map → project entry → current state → relevant decisions and evidence. This is a reading convention, not an automated retrieval engine.

When evidence changes, update the authoritative record and link to superseded reasoning. When records conflict, surface the conflict rather than trusting whichever timestamp is newest. A note's updated date is a maintenance signal, not proof that its contents are correct.

Knowledge is intentionally empty in the starter. Add conclusions earned through actual work.
