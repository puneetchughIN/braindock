# Portfolio Overview

Use this when the user explicitly asks for a portfolio overview.

Read the Projects index, then each linked project entry and its named current-state owner. Read relevant decisions, open threads, and recent meaningful changes as needed. Avoid loading entire source collections.

Produce a compact table: project, lifecycle from the index, evidenced current state, recent change, next meaningful move, and blocker or uncertainty. Cite the underlying records. Distinguish an outdated record from an incomplete project. Do not invent progress percentages.

Prefer portable Markdown. A visual may be used if the current environment supports it and the user's request permits it. The summary is a dated view, not a new source of truth.

Stay read-only: no note refreshes, lifecycle changes, task dispatch, external services, or Git mutations. If evidence conflicts, report it rather than repair it.
